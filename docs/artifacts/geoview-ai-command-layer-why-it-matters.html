One surface, two kinds of user

People and AI drive the same commands

There is one set of read-only commands over the live project. A person reaches them in natural language; an AI reaches them as tool calls. Same surface, same real data, same machine-readable answers.

Human user

🧑‍🔬 Ask in plain language

Type a question or a short phrase in the in-app assistant. No menu hunting, no manual steps — the app answers.

list wells
→ "This project has 4 wells…"
AI user

🤖 Call as a tool

An AI agent issues the exact same command as a structured call and receives JSON it can parse, check, and reason over — no screen to interpret.

{"command":"well.list"}
→ {"ok":true,"wells":[…4…]}

Both paths converge on ~24 read-only commands that return the same structured result — so whatever a person can ask, the AI can ask too.

The payoff — a development feedback loop

The AI can verify its own work

The real leverage shows up during development. When an AI fixes a bug or adds a feature, it can call this tool to exercise the change on a real project, get the result back, see it, and judge whether the change is correct — then iterate. Objective feedback, in the loop, without waiting for a human to click through the app.

Without it

  • Rebuild, then click through the GUI by hand
  • Eyeball a screen — the AI can't "see" a window
  • Correctness is a guess until a human checks
  • Feedback waits for the next review cycle

With it

  • Exercise the change with one command
  • Result returns as data the AI can parse
  • Correctness is checked against real numbers

Why it works

What makes the loop trustworthy

Machine-readable

Results as data

Every command returns structured JSON — something an AI can parse and assert on, not a screenshot to interpret.

Real data

Verified on real projects

Commands run against actual surveys (e.g. GOM V3), not mocks — so a passing check actually means something.

Headless

No clicking required

One layer

Reused everywhere

Safe by design

Human-gated writes

The AI-driven surface is read-only queries, analysis, and opening dialogs; anything that changes data stays a human action. Local-first — project data stays on-prem.

Deterministic

Reliable dispatch

A real instance

Built with its own medicine

Loop in action · GOM V3

This tool verified the code that built it

While developing the command layer, the AI used the layer itself to check each change on a real project — closing the loop on its own work. After adding volume comparison, it ran a self-compare and confirmed the scan math from the returned numbers:

compare volumes --volume-a AG_Spec_Bal --volume-b AG_Spec_Bal
→ {"compatible":true,"traces":23715,"rms_diff":0,"correlation":1.0}
// identical inputs → correlation 1.0, zero difference — the diff path is correct.

Same pattern verified list wells (4 wells), stats volume (amplitudes), and spectrum volume (a Bandpass suggestion) — each change confirmed against real returned values before moving on.

The interface is the bridge. The feedback loop is the payoff.

Link an AI to GeoView and it stops being a black box: the AI drives it, sees the result, and verifies its own changes — so building on GeoView gets faster and safer at the same time.
